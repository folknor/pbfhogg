I found the following issues in this scope. This was a read-only review of the scripts, configuration, testing records, relevant ADRs, brokkr's manuals, and the brokkr implementation behind verify. I ran no benchmarks or verifies, so costs below are operation counts or data volumes, not measured timings.

1. **Requested stop markers can silently stop doing anything.** [stop.lua](/home/folk/Programs/pbfhogg/benches/lib/stop.lua:7) validates spelling, and [profiling.lua](/home/folk/Programs/pbfhogg/benches/lib/profiling.lua:4) forwards the resolved name. The scripts accept an ordinary successful completion when `r.stopped_at` is absent. Brokkr explicitly documents that a missing marker lets the child finish normally. Renaming a marker therefore turns a phase-limited run into a full run without failing it, potentially adding the rest of a planet operation.

   Make a requested stop a required observation. A shared result helper should fail when `stop` was supplied but the child did not reach it. Enforce this with helper tests for reached, missing, and renamed markers, plus a rule requiring stop-capable scripts to use that helper.

2. **`ref-integrity --check-relations yes` reads the wrong expectation.** [ref-integrity.lua](/home/folk/Programs/pbfhogg/benches/check-refs/ref-integrity.lua:19) always selects `expect.check-refs`. Brokkr's dataset documentation defines a separate `check-refs-relations` expectation because way references can be clean while relation references are broken. The script ignores that distinction.

   Select the expectation from the actual check configuration, as `location-integrity` already does for agreement mode. A small script contract test with different plain and relation expectations can enforce this and catch both false acceptance and false rejection.

3. **Expected answers disappear silently when their lookup keys stop matching.** [diff-pair.lua](/home/folk/Programs/pbfhogg/benches/diff/diff-pair.lua:25) looks up an expected verdict using configured hashes. Missing hashes, a changed hash, or an obsolete pair key produces `want = nil`, after which either answer passes. [diff-applied.lua](/home/folk/Programs/pbfhogg/benches/diff/diff-applied.lua:35) similarly loses its assertion when the OSC key no longer matches. The integrity benches also accept either clean or violations when their expectation is absent.

   Optional expectations are reasonable for exploratory timing, but these runs need to distinguish “observed an answer” from “checked the declared answer.” Add an explicit assertion mode that requires an expectation, record whether one was applied, and reject orphaned expectation keys in a configuration check. These are mechanically enforceable; deciding the correct expected answer still requires an independent oracle.

4. **Several workload names describe paths the scripts never establish.** [diff-unindexed.lua](/home/folk/Programs/pbfhogg/benches/diff/diff-unindexed.lua:28) checks that paths differ, but never checks that either input lacks indexdata. Its claimed sequential comparison can become an indexed comparison while still passing. [dedupe-pair.lua](/home/folk/Programs/pbfhogg/benches/cat/dedupe-pair.lua:37) does not require passthrough or coalesced copying, despite describing those as its purpose. Its `--check yes` also assumes the second input is a content subset of the base without establishing that precondition.

   Give workloads explicit eligibility and coverage predicates: index absence, nonzero passthrough, and the intended subset relationship. Check input properties outside the measured child and execution properties from counters afterward. A counter or property disappearing should fail coverage. This can be enforced with script contract tests and typed workload declarations.

5. **The geocode instrument can report an apparent speedup while queries fail.** [run_bench_geocode_query](/home/folk/Programs/pbfhogg/crates/cli/src/lib.rs:5175) ignores query errors during timed rounds. Warm-up counts errors but still returns success, and [geocode-query.lua](/home/folk/Programs/pbfhogg/benches/build-geocode-index/geocode-query.lua:65) never rejects a nonzero error count. A revision that starts returning errors can complete less work and appear faster.

   Fail unexpected query errors, including during timed rounds. If error workloads are wanted, declare their expected outcomes separately. Enforce this with an instrument test using a reader abstraction that returns a deliberate query error.

6. **The geocode result parser accepts missing correctness evidence.** [geocode-query.lua](/home/folk/Programs/pbfhogg/benches/build-geocode-index/geocode-query.lua:69) requires only `us_per_query_best`. Missing `admin_digest`, round timings, counts, or errors remain acceptable; renamed fields quietly disappear. The digest also covers only admin level and name. Address, street, and interpolation results contribute counts but not their values, so unchanged counts can hide changed answers.

   Emit a versioned structured result and validate every required field, numeric range, round count, and digest shape. Hash the complete answer when claiming answer equivalence. Parser mutation tests can enforce the schema; fixtures with equal counts but different answer values can enforce digest coverage.

7. **Every geocode-query iteration rebuilds the entire index.** [geocode-query.lua](/home/folk/Programs/pbfhogg/benches/build-geocode-index/geocode-query.lua:47) builds an index before each measured query child. The build is excluded from the ranked wall but remains part of the actual cost. With the default three iterations, one query benchmark performs three full index builds and discards all three indexes.

   Split index production from query measurement. Reuse an immutable index keyed by input digest, producer identity, and build options, with ownership and retention in brokkr. That preserves revision-specific indexes while avoiding repeated identical builds. Enforce cache invalidation with tests that vary each key component.

8. **The default result metric often includes work the script tells readers to exclude.** Cache-controlled benches such as [diff-text.lua](/home/folk/Programs/pbfhogg/benches/diff/diff-text.lua:38), [dedupe-self.lua](/home/folk/Programs/pbfhogg/benches/cat/dedupe-self.lua:27), and [sort-cold.lua](/home/folk/Programs/pbfhogg/benches/sort/sort-cold.lua:22) tell readers to compare the command child's wall, but do not mark that child `measured = true`. Brokkr therefore ranks iterations using the whole block. Warm preparation adds one complete read per input per iteration; optional correctness checks add another command to that metric.

   Mark the intended child as measured. Keep setup cost visible separately. Enforce this structurally with a shared single-command workload helper and a script contract test that checks which call supplies the result.

9. **The buffered/io_uring merge comparison has a fixed predecessor bias.** [merge-workload.lua](/home/folk/Programs/pbfhogg/benches/merge/merge-workload.lua:27) always runs buffered first and io_uring second. The second child inherits the first child's cache and drive effects. Only buffered supplies the ranked result, so the run is also selected on buffered performance even when assessing io_uring.

   Make the backend a separate arm and interleave matched single-iteration runs with equivalent predecessors. Brokkr can enforce one backend per measured iteration and record the experimental order. Equal drive state cannot be proven completely, but the schedule and declared preparation can be enforced.

10. **The osmium comparison's matched-operation claim depends on defaults staying aligned.** [vs-osmium.lua](/home/folk/Programs/pbfhogg/benches/compare/vs-osmium.lua:15) states that both tools use zlib level 6, but neither command line pins that codec and level. Strategy and node-retention equivalence also partly depend on defaults. A default change can alter the work while leaving the comparison apparently valid. The benchmark only checks command success; it does not compare the produced results.

    Define each comparison row as an explicit operation contract, including codec, strategy, retention, durability, and equality policy. Generate argv from it and validate outputs in a separate correctness run. Contract tests can enforce flag selection; independent output comparison is needed to enforce equivalence.

11. **The comparison driver has already drifted from its advertised table.** [vs-osmium.sh](/home/folk/Programs/pbfhogg/scripts/vs-osmium.sh:7) says it runs every row, but omits the `extract` row added to the Lua script and registry. It also hardcodes OSC 4705 and offers no dataset selection. Its `PAIRS` argument is not validated: zero or negative values can finish successfully without running any cells.

    The current default schedules 63 bench invocations: ten paired rows times three pairs, plus three inspect runs. Generate the row selection from one registry, require a positive pair count, and resolve OSC selection through the selected dataset. A cheap driver test with a recording brokkr stub can enforce the invocation count and selected rows.

12. **Host config contains a known false replication sequence that executable consumers still accept.** [plantasjen.toml](/home/folk/Programs/pbfhogg/brokkr.d/hosts/plantasjen.toml:80) records that the north-america base is actually sequence 4700, while its entry says 4710 and offers OSC 4710 with intervening changes missing. The warning protects a reader, but `apply-diff` and `diff-applied` can bind those entries and run successfully. The result is a transformation of an incomplete update chain, not the claimed daily update.

    Correct or quarantine the entry and represent replication provenance as data. Validate configured sequence against the PBF header and require contiguous changes for workloads claiming a replication update. Header checks and chain validation are mechanical; where provenance is unavailable, the workload must explicitly state that continuity is unverified.

13. **Host identity changes coverage and build features.** The host configurations provide different datasets, bboxes, OSCs, expectations, and feature sets. For example, [dm6.toml](/home/folk/Programs/pbfhogg/brokkr.d/hosts/dm6.toml:1) has neither the feature list nor the bbox/OSC coverage of bygg. Brokkr adds host features to bench features, so moving the same invocation can change both its workload and its build. Unknown hosts have empty datasets and refuse default dataset binding; `verify all` reports skips for unavailable inputs.

    Separate machine resource placement from experiment definitions. Keep workload selection, required coverage, and build features in a host-independent experiment manifest. Enforce required capabilities and coverage before running it, and report missing coverage as incomplete certification. Resource availability can remain detected host state.

14. **Cache preparation reaches ambient utilities and changes shared host state.** The cache benches invoke GNU `dd` options and `fincore` from `PATH`, often passing raw `.path` strings. A host with missing or incompatible utilities refuses at runtime. Successful eviction also changes the input's shared page cache for other readers; brokkr's lock cannot exclude unrelated processes. The residency check is an observation before launch, not a guarantee throughout the command.

    Put cache preparation behind a brokkr operation that takes input handles, declares access, detects support, and records the residency observation. If utilities remain, preflight their required behavior. Support detection and declared access are enforceable; stable cache state throughout a run is not fully enforceable and should remain an explicit experimental limitation.

15. **Verify's equality oracle is narrower than “identical” and shares implementation with the subject.** [VerifyHarness::diff_pbfs](/home/folk/Programs/brokkr/src/pbfhogg/verify.rs:248) judges reference outputs using pbfhogg diff. [verify_sort](/home/folk/Programs/brokkr/src/pbfhogg/verify_sort.rs:62) prints “identical” for that result. But [content.rs](/home/folk/Programs/pbfhogg/crates/lib/src/content.rs:11) deliberately excludes metadata, inline way locations, headers, and encoding. A shared decoder defect can also affect both the transformation and its judge.

    State an equality policy per check and use an independent decoder for the fields promised by that operation. Full digest can strengthen same-project preservation checks, but shares implementation and is not an independent parity oracle. Enforce coverage with negative controls that alter metadata, locations, headers, and content separately and require the appropriate comparisons to reject them.

16. **Verify still uses the build tool's output directory as its workspace.** [VerifyHarness](/home/folk/Programs/brokkr/src/pbfhogg/verify.rs:58) places outputs under `<target>/verify`, and `subdir` recursively replaces each check's fixed directory. Cargo owns `target`; these potentially large PBFs, listings, and reports have a separate lifecycle, disappear with build cleanup, and overwrite previous evidence.

    Put disposable verify work under a brokkr-owned per-run directory beneath configured scratch. Publish retained failure evidence into a separate brokkr-owned artifact area with explicit retention. Enforce this through directory capability types rather than allowing checks to construct arbitrary target-relative paths.

17. **Optional context tools add cost and provisioning dependencies without contributing a verdict.** `verify all` attempts to provision osmosis, and [run_context_tools](/home/folk/Programs/brokkr/src/pbfhogg/verify_merge.rs:246) runs osmosis and osmconvert for context only. Their failures do not change the comparison verdict. On a cache miss this can add provisioning, a JVM launch, full input processing, and additional output files to an otherwise focused correctness check.

    Make context comparisons an explicit diagnostic option. The default correctness graph should contain only producers consumed by assertions. A declarative step graph can mechanically reject unused outputs or require an explicit diagnostic designation.

18. **The Lua checks do not exercise these behavioral contracts.** Brokkr's bench check compiles registered scripts and modules and resolves global names. Its manual explicitly says that wrong option keys, argument types, nil values, and behavior inside functions are discovered only when that code runs. Dry-run executes validation, not the workload. Consequently, a green standard check does not detect the wrong relation expectation, missing stop observation, or incomplete geocode result schema above.

    Add a script contract harness with controlled implementations of `binary`, handles, results, configuration, and recording. Exercise generated argv, required observations, failure paths, and result schemas without datasets or external tools. Also enforce registry discovery: today all 32 executable Lua scripts are registered and present, but nothing in the reviewed project rules requires a newly added script to be registered.

19. **Repeated parameter validation is already diverging.** Unsigned integer parsing is copied across jobs and region parameters. Bbox validation differs between extraction and geocode: geocode's splitter skips empty fields and does not check finite values or geographic bounds; its integer validators do not enforce the Rust argument widths. Invalid values can pass validation and fail only after building, or after index setup.

    Move parameter types into brokkr's schema or shared validated constructors: bounded integers, finite geographic boxes, and compression specifications. Enforce their use with contract tests and a source rule against local replacements. This also removes repeated textual policy from the registry and script headers.

20. **The testing record contains a false coverage claim.** [reference/testing.md](/home/folk/Programs/pbfhogg/reference/testing.md) says brokkr verify has no locations-on-ways path. Current [verify_all.rs](/home/folk/Programs/brokkr/src/pbfhogg/verify_all.rs:251) explicitly runs that path when the keep-untagged base resolves. The missing capability described there needs narrowing to what actually remains unavailable, such as accepting the handcrafted fixture through the required interface.

    Generate capability and supported-path inventories from command declarations or expose a machine-readable describe interface. Documentation checks can enforce generated inventories. The explanation of why a particular handcrafted fixture remains necessary still needs review.

I found no nested build-tool invocation in the Lua scripts: their `binary()` calls already use brokkr's built artifact. I also found no sleep-based synchronization or shared mutable Lua singleton in this scope. The recurring costs here come chiefly from repeated setup, extra context executions, full-file cache preparation, and measurements whose default ranking includes work their own instructions tell readers to exclude.
