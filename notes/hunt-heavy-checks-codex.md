The first rewrite should be **degrade and repack as multi-output verification jobs**. Degrade alone makes seven full element comparisons on a qualifying input, and five of its outputs also get two payload audits. The next largest opportunities are one shared judgment pass for both add-locations engines, a streaming apply-changes model, and a sort oracle that can recognize an already ordered input. These are source-based rankings. I did not build, test, run benchmarks, or modify files.

## 1. Degrade and repack need a full rewrite of the verification path

A normal indexed `degrade` runs six producers under five distinct case configurations. It decodes the base reference for strip-locations, both distinct drop seeds, and both unsort cases. The first drop output is decoded three times across its comparison with the base, its repeat, and the other seed. Each of the five audited outputs also gets the verifier's independent ID decode, `check --index`, a claims walk, and case-specific layout work. Repack repeats the same pattern across four cases. Its layout predictor alone opens and walks the original claims once per kind per case. On a locations base, degrade also writes a coordinate-free reference PBF and compares full decodings of the two reference views. The reference gets decoded for order twice. The location judge itself decodes nodes for keys and again for coordinates, and with agreement it reads way refs before its per-partition way scans. It decodes osmium's output to OPL, copies its untouched records to `expected.opl` while inserting modeled winners, then reads that file back against another full OPL decode. Before that, it scans the base with `osmium getid -H -I`, runs extended fileinfo on the reference for context, and separately decodes pbfhogg's output for order. ## 4. Sort, cat and cat-dedupe can commission much less reference work

- **Sort is a high-payoff oracle rewrite.** The current check runs osmium multipass even when independent decoding would prove that the input is already strictly ordered. In that case a stable sort cannot permute any object. Use the independently read input sequence with the same reference projection, and on disorder use an independent stable sort that emits comparison records directly. Keep osmium's type, signed ID and version ordering, duplicate rejection, and the way-location keep/drop prediction. The input header alone is insufficient evidence. Establish equivalence to osmium's PBF write/read normalization before bypassing it, particularly for visibility and coordinates. This removes the full sort and intermediate PBF on the already-ordered route. The `sort` multipass artifact also differs from the simple-sort artifact other checks request. The simple path writes a sort declaration, and the cache distinguishes their argv. A shared ordered reference should provide a declared PBF only to consumers that actually need one. ## 5. OSC models and the remaining checks

- **Merge-changes warrants its own model rewrite for large OSC inputs.** It concatenates listings for the input and again for its replay, externally sorts occurrence descriptors, seeks to payloads one survivor at a time, and sorts survivors again by action. Fold histories by signed identity from the XML and osmium occurrence streams. Retain the first version claim, high water mark, first regression position, last record and the state needed for osmium's winner. On replay, the last-record sequence is identical, and a cross-copy regression can be found from the first explicit claim below the first copy's floor, unless an earlier in-copy regression already wins. The osmium winner can be reused in the ordered timestamp domain, while mixed timestamps need the existing skip and faithful diagnostics. Emit expected simplify records in three action streams from the ordered identities, and compare default mode against a chain of the original listings. Keep the once and replay program invocations, both job modes, default decompressed-byte parity, and osmium `-s` where defined. Building the fixture model twice is a straightforward local cut. ## Handoffs to the shared scopes

The compare engine needs reusable decoded sources, exact per-policy projections, frame provenance, and streaming comparison callbacks. It can start with libosmium as the independent decoder. The library's `ElementReader`, ID projections and full-digest writer are useful for native facts and same-project judgments. They have different admission, field and ordering semantics from the verifier's independent readers. A library digest or plain content diff cannot stand in for osmium's record comparison. Orchestration has concrete duplicates to remove. `diff` and `diff --format osc` independently build the same buffered applied PBF. Check-ids' buffered cross-blob `--unsort` uses the same cap of 8000 as degrade, so those checks can share an eligible artifact after matching the effective invocation. Its intra-blob input has indexdata stripped and needs that distinct framing. Share the OSC occurrence stream across the two apply modes and merge-changes, while keeping base-specific lookups and each consumer's domain checks.
